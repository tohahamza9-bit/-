# ملاحظات التكامل (م1.5) — قرارات وتشغيل

بعد بناء الوحدات الثماني (A1–A8)، رُبطت في الأنبوب `core/pipeline.py` (§15) والتطبيق `core/app.py`.
هذا الملف يوثّق قرارات التكامل التي اتُّخذت لحلّ التعارضات بين الوحدات.

## الحالة النهائية
- **Python:** 137 اختبارًا ناجحًا (وحدات + تكامل + تطبيق).
- **Node (Baileys):** 25 اختبارًا ناجحًا.
- **الوحدات:** الفهم، الطابور، المطابقة، الكاتب، التحقّق، الحارس، اللوحة، واتساب — كلها مرتبطة.

## قرارات التكامل (تعديلات محسوبة على وحدات الوكلاء)

### 1) تجميع الطرفين حين الخزينة غير محلولة (§5.5، §7.3) — `core/queue/service.py`
المشكلة: الطرف البائع في صفقة طرفين قد يصل أولًا بلا خزينة صريحة (`expects_pair=False`)، فلا
ينتظر ولا يُجمَع مع الشراء اللاحق → مخالفة §7.3 «البيع لا يُسجَّل قبل اكتمال الصفقة».
الحل: الطابور ينتظر طرفًا ثانيًا أيضًا حين تكون الخزينة **غير محلولة** (غموض = ننتظر — القاعدة الذهبية §0).
الخزينة «بيع فقط» المحلولة (بلاس/وليد...) تمشي فورًا كما في §5.2 (لا تباطؤ للمسار السريع).

### 2) رسائل التحكّم تُعالَج فورًا (§10) — `core/pipeline.py`
المشكلة: ردود مثل «إلغاء»/«تم» قصيرة، فكانت وحدة الاستقرار تعاملها كـ«حرف» placeholder وتؤخّرها 90s.
الحل: رسالة تحكّم عبر Reply = إجراء مكتمل متعمّد → تُعالَج فورًا بلا انتظار استقرار
(انتظار «الحرف» في §7.2 يخصّ الحوالات الجديدة القصيرة، لا الردود).

### 3) توحيد المناطق الزمنية (naive/aware) — `stabilization.py`, `matching/service.py`, `guard/corrections.py`
المشكلة: MongoDB/mongomock قد تُرجع أوقاتًا بلا منطقة (naive) بينما `utcnow()` بمنطقة (aware) →
`TypeError` عند الطرح. الحل: دالة `_as_naive_utc` تُطبَّق في كل مواضع المقارنة الزمنية
(كانت مطبَّقة في `queue/service.py`؛ عُمّمت على البقية).

### 4) خصم/خزينة الطرفين تُحسم في الأنبوب (§6) — `core/pipeline.py::_resolve_two_leg`
عند اكتمال صفقة طرفين: يحسب الأنبوب العمولة (`compute_commission`) ويُسند خزينة «خصم1%/صافي»
(`resolve_two_leg_treasury`) لطرفَي الصفقة قبل الكتابة.

### 5) بوّابة قبل الكتابة تحترم الأكواد المعلّقة (§ملحق ب-3)
خزينة بلا كود MONEYADO (خصم1%/صافي/هادم — معلّقة) → بوابة الثقة تعلّق ⚠️ ولا تُنزّل حتى يُستكمل
الكود من Dashboard. هذا يحقّق §0 (لا تنزيل عند الغموض) دون تعطيل باقي الأنواع.

## كيفية التشغيل

### تطوير/اختبار
```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # يشمل fastapi/uvicorn
.venv/Scripts/python -m pytest                      # 137 اختبارًا
node --test whatsapp/test/                           # 25 اختبارًا
```

### تشغيل النظام (على الجهاز الفرعي)
1. انسخ `.env.example` → `.env` واملأ: MONGO_URI، الغرف (JID)، INTERNAL_TOKEN، SQL_DSN (بعد §16 م0).
2. انسخ `config/moneyado_fields.example.json` → `moneyado_fields.json` واستكمل `auto_id` بفحص
   `print_control_identifiers` (§11.3). بدونها الكاتب يرفض التعبئة (لا تخمين).
3. انسخ `config/sql_queries.example.json` → `sql_queries.json` واملأ أسماء الجداول، وفعّل `SQL_ENABLED`.
4. شغّل خدمة واتساب: `cd whatsapp && npm install && npm start` (QR أول مرة).
5. شغّل النواة: `.venv/Scripts/uvicorn core.app:get_app --factory --port 8000`.
6. افتح اللوحة `http://<host>:8000/` — **التخزين افتراضيًا إيقاف (§13)**. فعّله تدريجيًا (§16 م2).

## المعلّقات التقنية المتبقّية (ملحق ب) — تُستكمل وقت التنفيذ، لا تعطّل البناء
1. `auto_id` لخانات الشاشتين → `config/moneyado_fields.json`.
2. أسماء جداول SQL → `config/sql_queries.json`.
3. أكواد خزائن هادم/خصم1%/صافي/تونسي خارجي → من Dashboard (البوت يعلّق ⚠️ حتى تُضاف).
4. معرّفات الغرف (JID) → `.env` + Dashboard.
